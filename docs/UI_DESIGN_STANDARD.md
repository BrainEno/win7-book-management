# Win7 Book Management UI 设计与验收标准

本文件是 Win7 版本的 UI 单一标准。后续页面重构必须优先遵守本文件，而不是在每个 Form 内自行决定尺寸、颜色和布局。

## 1. 兼容性优先级

1. Windows 7 SP1 + .NET Framework 4.8 是硬约束。
2. 运行时只使用 WinForms / GDI+ 能稳定支持的能力，不引入 WebView2、WinUI、WPF 宿主或只支持 Windows 10/11 的视觉框架。
3. 所有主页面必须在 1024×768 可操作，在 Windows 10/11 的 2K / 4K + DPI 缩放下不截断主要信息。
4. 优先通过响应式列隐藏、侧栏折叠、间距压缩和可伸缩布局解决小窗口问题；滚动条是最后手段。

## 2. 是否更换第三方 UI 组件库

本阶段不更换第三方 UI 组件库。

原因不是“继续接受原生 WinForms 的默认外观”，而是将原生 WinForms 当作兼容层，在项目内部建立统一 Design System。现有问题主要来自：

- 单行 TextBox 仍使用默认高度，导致高 DPI 下文字上下被裁切；
- Form 内大量绝对高度与固定列宽，DPI 放大后没有足够空间；
- 页面缺少明确的“工具栏 / 输入区 / 数据区 / 结算区 / 摘要区”层级；
- 各页面自己决定 padding、字号、按钮大小，缺少统一 token；
- 数据表没有按窗口宽度隐藏次要列；
- 表单用碎片化小卡片堆叠字段，字段对齐和阅读顺序不稳定。

这些问题不需要通过大型第三方皮肤库才能解决。引入第三方库反而会增加 Win7、x86、离线 installer、授权和原生 DLL 风险。

未来只有候选库同时满足以下条件才允许重新评估：

- 明确支持 .NET Framework 4.8；
- 明确支持 Windows 7 SP1；
- x86 构建和离线部署无附加在线依赖；
- 不依赖 WebView2 / Windows App SDK / WinUI 3；
- 商用许可清晰；
- 1024×768、100%/125%/150% DPI 和 Win10/11 4K 实机 smoke test 通过；
- 能显著减少维护成本，而不是只提供皮肤。

## 3. Design Tokens

统一定义在 Infrastructure/UiTheme.cs。

### 色彩

- Background：暖灰工作区背景。
- Surface：主卡片、表格、输入区。
- SurfaceMuted：表头、摘要条等次级背景。
- Accent：主操作、选中态。
- AccentSoft：表格选中和弱强调。
- TextPrimary：主要文字。
- TextSecondary：说明、标签。
- Border：所有卡片、输入、表格的统一边框。
- Warning / Danger / Success：只用于真实状态。

禁止页面自行大量定义随机 RGB。

### 字体

字体按以下顺序回退：

1. Microsoft YaHei UI
2. Microsoft YaHei
3. Segoe UI
4. SimSun
5. 系统 MessageBox 字体

主要字号：

- 页面 / Dialog 主标题：12–14 pt，Bold。
- 区块标题：9.5–11 pt，Bold。
- 正文 / 输入：8.5–10 pt。
- 辅助文字：8 pt 左右。

禁止用过小字体换取“塞得下”。

### 控件高度

- 标准输入框：38 logical px。
- 标准按钮：38 logical px。
- DataGridView 行：38 logical px。
- DataGridView 表头：40 logical px。

单行 TextBox 必须显式 AutoSize=false，否则 WinForms 会忽略期望高度。

## 4. 页面结构

商业操作页应优先使用清晰的 4–5 区结构：

1. 页面级动作工具栏。
2. 搜索 / 扫码 / 主要输入区。
3. 主数据表格或工作区。
4. 当前操作的辅助区域，例如结算、备注、筛选。
5. 底部摘要 / 主确认动作。

同一层级的区块边缘必须对齐。

## 5. 表单字段 Grid

新增 / 编辑资料 Dialog：

- 默认 2 列字段 Grid；
- 同类字段放在同一区块；
- 主字段（如书名）可以跨 2 列；
- 不在每个字段下永久放一大段说明，次要说明优先用 ToolTip；
- 字段标签、输入框必须上下对齐；
- 多行备注独立占整行；
- Footer 固定保存 / 取消，Body 可滚动；
- Dialog 必须能缩小到 Win7 常见屏幕可用范围。

## 6. DataGridView 标准

- 表头不换行。
- 主要字段：书名、数量、金额始终优先保留。
- 较窄窗口先隐藏次要列，不允许仅靠横向滚动解决。
- 数字右对齐；金额统一 0.00。
- 表格选中态不能把文字对比度降到难以阅读。
- 低库存等状态允许改变文字色，但不允许覆盖选中可读性。

## 7. 响应式断点

当前统一断点：

- Compact：< 980 logical px
- Wide：>= 1180 logical px

典型行为：

- 商品资料页在非 Wide 宽度隐藏右侧详情面板；
- 表格按可用宽度依次隐藏出版社、装帧、出版年等次要列；
- 工具栏允许 Wrap；
- 主输入区保留完整输入框和主按钮。

## 8. 第一阶段重构范围

第一阶段优先对齐 Flutter 版本的信息架构，而不是机械复制 Flutter 组件：

### 零售开单

- 顶部动作区；
- 独立商品输入区；
- 大面积购物车表格；
- 结算备注区；
- 底部商品项、合计数量、应收金额、确认结账；
- 1024 宽度自动隐藏次要表格列。

### 图书资料

- 顶部查询卡；
- 新增 / 编辑 / 包含停用放在一致的动作区；
- 统计 chip；
- 主表格；
- 宽屏右侧“基本信息”详情面板；
- 小窗口自动折叠详情面板；
- 编辑 Dialog 按“基础信息 / 分类与出版 / 价格信息 / 经营备注”重组。

## 9. 验收矩阵

每个主页面完成后至少检查：

- 1024×768，100% DPI；
- 1366×768，100% DPI；
- 1920×1080，100% / 125% DPI；
- 4K，150% / 200% DPI；
- 文字是否完整显示；
- 输入框高度是否足够；
- 主按钮是否完整可见；
- 缩小窗口时是否先隐藏次要信息；
- Tab 键顺序是否基本合理；
- DataGridView 是否仍能看到核心字段；
- Dialog 是否可保存 / 取消且 Footer 不被 Body 挤掉。

Win7 真机 smoke test 仍是发布前最终门槛。


## 10. 第二阶段重构范围

### 采购入库

- 页面结构与零售开单保持同一套工作流骨架：动作栏 → 入库信息 → 明细表格 → 备注 → 底部汇总与确认。
- 供应商明确标记为可选，并提供“未指定供应商”选项，避免用户误以为必须先建供应商才能入库。
- 明细表格包含店内编码、ISBN、书名、货架位、当前库存、入库数量、本次进价和小计。
- 本次进价允许覆盖图书资料中的默认进价，但不会回写历史采购单。
- 窄窗口依次隐藏店内编码、货架位、ISBN、当前库存等次要列。
- 空白状态、清空当前单、离开未提交单据确认都必须可见且明确。

### 库存管理

- 顶部查询区统一展示搜索、仅看低库存、结果数量、低库存数量和当前筛选结果的库存总册数。
- 宽屏提供右侧“库存详情”，展示书名、编码、ISBN、作者、分类、货架位、当前库存、低库存阈值和库存状态。
- 非 Wide 宽度自动折叠详情区，并按优先级隐藏次要列。
- 库存调整 Dialog 不再要求用户理解“正数 / 负数”，改为明确的“增加库存 / 减少库存 + 调整数量”。
- Dialog 必须实时预览调整后库存，减少库存不能产生负数，且调整原因必须填写。
- 每次库存调整仍然只通过 InventoryService 写入库存和库存流水，不允许 UI 直接修改 stock_quantity。

### 共享图书选择器

- 销售与采购共用同一套图书选择 Dialog。
- 搜索字段覆盖店内编码、ISBN、书名、作者、出版社、分类、出版信息、装帧、货架位和备注。
- 表格优先保留书名、库存等核心字段，窄窗口按优先级隐藏店内编码、货架位、作者、零售价和 ISBN。
- Dialog 尺寸自动限制在当前工作区内，避免 Win7 小屏或高 DPI 下按钮跑出屏幕。
