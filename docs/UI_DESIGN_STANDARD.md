# Win7 Book Management UI 设计与验收标准

本文件是 Win7 版本的 UI 单一标准。后续页面重构必须优先遵守本文件，而不是在每个 Form 内自行决定尺寸、颜色和布局。

## 1. 兼容性优先级

1. Windows 7 SP1 + .NET Framework 4.8 是硬约束。
2. 运行时只使用 WinForms / GDI+ 能稳定支持的能力，不引入 WebView2、WinUI、WPF 宿主或只支持 Windows 10/11 的视觉框架。
3. 所有主页面必须在 1024×768 可操作，在 Windows 10/11 的 2K / 4K + DPI 缩放下不截断主要信息。
4. 优先通过响应式列隐藏、侧栏折叠、间距压缩和可伸缩布局解决小窗口问题；滚动条是最后手段。

## 2. 是否更换第三方 UI 组件库

本阶段不更换第三方 UI 组件库。

原因不是“继续接受原生 WinForms 的默认外观”，而是将原生 WinForms 当作兼容层，在项目内部建立统一 Design System。现有问题主要来自：

- 单行 TextBox 被强行拉高或塞进过矮的固定行，原生 WinForms 文本基线会失衡；
- Label / TableLayoutPanel 大量使用 18–34px 固定高度，雅黑 / 高 DPI 下容易把字形裁掉；
- Form 内大量绝对高度与固定列宽，DPI 放大后没有足够空间；
- 页面缺少明确的“工具栏 / 输入区 / 数据区 / 结算区 / 摘要区”层级；
- 各页面自己决定 padding、字号、按钮大小，缺少统一 token；
- 数据表没有按窗口宽度隐藏次要列；
- 表单用碎片化小卡片堆叠字段，字段对齐和阅读顺序不稳定。

这些问题不需要通过大型第三方皮肤库才能解决。引入第三方库反而会增加 Win7、x86、离线 installer、授权和原生 DLL 风险。

未来只有候选库同时满足以下条件才允许重新评估：

- 明确支持 .NET Framework 4.8；
- 明确支持 Windows 7 SP1；
- x86 构建和离线部署无附加在线依赖；
- 不依赖 WebView2 / Windows App SDK / WinUI 3；
- 商用许可清晰；
- 1024×768、100%/125%/150% DPI 和 Win10/11 4K 实机 smoke test 通过；
- 能显著减少维护成本，而不是只提供皮肤。

## 3. Design Tokens

统一定义在 Infrastructure/UiTheme.cs。

### 色彩

- Background：暖灰工作区背景。
- Surface：主卡片、表格、输入区。
- SurfaceMuted：表头、摘要条等次级背景。
- Accent：主操作、选中态。
- AccentSoft：表格选中和弱强调。
- TextPrimary：主要文字。
- TextSecondary：说明、标签。
- Border：所有卡片、输入、表格的统一边框。
- Warning / Danger / Success：只用于真实状态。

禁止页面自行大量定义随机 RGB。

### 字体

字体按以下顺序回退：

1. Microsoft YaHei UI
2. Microsoft YaHei
3. Segoe UI
4. SimSun
5. 系统 MessageBox 字体

主要字号：

- 页面 / Dialog 主标题：12–14 pt，Bold。
- 区块标题：9.5–11 pt，Bold。
- 正文 / 输入：8.5–10 pt。
- 辅助文字：8 pt 左右。

禁止用过小字体换取“塞得下”。

### 控件高度与字体度量

- 按钮使用 38 logical px 作为 96 DPI 最小高度，并同时保证至少容纳“实际字体高度 + 16px”。
- 单行 TextBox 不再强制 AutoSize=false 或硬拉到 38px。原生 WinForms 单行 TextBox 必须保留系统文本基线，外层布局负责提供足够的上下空间。
- ComboBox / NumericUpDown / DateTimePicker 使用内容驱动的最小高度，不能依靠过小的固定 TableLayout 行。
- DataGridView 行与表头的最小高度根据实际字体度量计算；38 / 40px 只作为 96 DPI 下的最低基线。
- 普通单行 Label 禁止使用 18 / 20 / 22px 一类“刚好塞字”的固定高度；优先 AutoSize，确需固定行时必须由全局 DPI 安全层校验实际字体高度。
- 文本行与字段标题行优先使用 SizeType.AutoSize。

## 4. 页面结构

商业操作页应优先使用清晰的 4–5 区结构：

1. 页面级动作工具栏。
2. 搜索 / 扫码 / 主要输入区。
3. 主数据表格或工作区。
4. 当前操作的辅助区域，例如结算、备注、筛选。
5. 底部摘要 / 主确认动作。

同一层级的区块边缘必须对齐。

## 5. 表单字段 Grid

新增 / 编辑资料 Dialog：

- 默认 2 列字段 Grid；
- 同类字段放在同一区块；
- 主字段（如书名）可以跨 2 列；
- 不在每个字段下永久放一大段说明，次要说明优先用 ToolTip；
- 字段标签、输入框必须上下对齐；
- 多行备注独立占整行；
- Footer 固定保存 / 取消，Body 可滚动；
- Dialog 必须能缩小到 Win7 常见屏幕可用范围。

## 6. DataGridView 标准

- 表头不换行。
- 主要字段：书名、数量、金额始终优先保留。
- 较窄窗口先隐藏次要列，不允许仅靠横向滚动解决。
- 数字右对齐；金额统一 0.00。
- 表格选中态不能把文字对比度降到难以阅读。
- 低库存等状态允许改变文字色，但不允许覆盖选中可读性。

## 7. 响应式断点

当前统一断点：

- Compact：< 980 logical px
- Wide：>= 1180 logical px

典型行为：

- 商品资料页在非 Wide 宽度隐藏右侧详情面板；
- 表格按可用宽度依次隐藏出版社、装帧、出版年等次要列；
- 工具栏允许 Wrap；
- 主输入区保留完整输入框和主按钮。

## 8. 第一阶段重构范围

第一阶段优先对齐 Flutter 版本的信息架构，而不是机械复制 Flutter 组件：

### 零售开单

- 顶部动作区；
- 独立商品输入区；
- 大面积购物车表格；
- 结算备注区；
- 底部商品项、合计数量、应收金额、确认结账；
- 1024 宽度自动隐藏次要表格列。

### 图书资料

- 顶部查询卡；
- 新增 / 编辑 / 包含停用放在一致的动作区；
- 统计 chip；
- 主表格；
- 宽屏右侧“基本信息”详情面板；
- 小窗口自动折叠详情面板；
- 编辑 Dialog 按“基础信息 / 分类与出版 / 价格信息 / 经营备注”重组。

## 9. 验收矩阵

每个主页面完成后至少检查：

- 1024×768，100% DPI；
- 1366×768，100% DPI；
- 1920×1080，100% / 125% DPI；
- 4K，150% / 200% DPI；
- 文字是否完整显示；
- 输入框高度是否足够；
- 主按钮是否完整可见；
- 缩小窗口时是否先隐藏次要信息；
- Tab 键顺序是否基本合理；
- DataGridView 是否仍能看到核心字段；
- Dialog 是否可保存 / 取消且 Footer 不被 Body 挤掉。

Win7 真机 smoke test 仍是发布前最终门槛。


## 10. 第二阶段重构范围

### 采购入库

- 页面结构与零售开单保持同一套工作流骨架：动作栏 → 入库信息 → 明细表格 → 备注 → 底部汇总与确认。
- 供应商明确标记为可选，并提供“未指定供应商”选项，避免用户误以为必须先建供应商才能入库。
- 明细表格包含店内编码、ISBN、书名、货架位、当前库存、入库数量、本次进价和小计。
- 本次进价允许覆盖图书资料中的默认进价，但不会回写历史采购单。
- 窄窗口依次隐藏店内编码、货架位、ISBN、当前库存等次要列。
- 空白状态、清空当前单、离开未提交单据确认都必须可见且明确。

### 库存管理

- 顶部查询区统一展示搜索、仅看低库存、结果数量、低库存数量和当前筛选结果的库存总册数。
- 宽屏提供右侧“库存详情”，展示书名、编码、ISBN、作者、分类、货架位、当前库存、低库存阈值和库存状态。
- 非 Wide 宽度自动折叠详情区，并按优先级隐藏次要列。
- 库存调整 Dialog 不再要求用户理解“正数 / 负数”，改为明确的“增加库存 / 减少库存 + 调整数量”。
- Dialog 必须实时预览调整后库存，减少库存不能产生负数，且调整原因必须填写。
- 每次库存调整仍然只通过 InventoryService 写入库存和库存流水，不允许 UI 直接修改 stock_quantity。

### 共享图书选择器

- 销售与采购共用同一套图书选择 Dialog。
- 搜索字段覆盖店内编码、ISBN、书名、作者、出版社、分类、出版信息、装帧、货架位和备注。
- 表格优先保留书名、库存等核心字段，窄窗口按优先级隐藏店内编码、货架位、作者、零售价和 ISBN。
- Dialog 尺寸自动限制在当前工作区内，避免 Win7 小屏或高 DPI 下按钮跑出屏幕。


## 11. 第三阶段重构范围

### 单据中心

- 顶部改为正式查询区：单据类型、起止日期、关键词和查询按钮必须在同一信息层级内。
- 查询区显示当前结果的单据数量与金额汇总；销售、采购、销售退货、采购退货分别使用对应金额语义。
- 单据列表与书目明细保持上下分区，窗口高度变化时按比例调整，不使用固定死高度。
- 自动生成的 DataGridView 列必须重新应用统一宽度、数字右对齐、书名 / 备注 Fill 规则。
- 窄窗口优先隐藏备注、供应商等次要信息；ISBN 等字段在明细区按宽度隐藏。
- 没有查询结果或没有选中单据时必须显示明确 Empty State。
- “发起退货”只对原销售单 / 原采购单可用；退货单本身不能再次作为退货来源。

### 销售退货 / 采购退货

- Dialog 顶部必须明确显示退货类型和原单号。
- 明确说明销售退货会按原售价退款并加回库存；采购退货按原进价计算并扣减库存。
- 退货表格清楚区分原数量、已退、可退、当前库存（采购退货）、原价格和本次退货数量。
- 增加“全部填为最大可退”和“清零本次退货”辅助操作；采购退货的最大数量同时受可退数量和当前库存限制。
- Footer 必须实时汇总退货项目数、退货册数和退款 / 退货金额。
- 提交前再次确认库存影响；原单据与历史价格永远不被改写。
- 窄窗口优先隐藏 ISBN、已退、当前库存等次要列，书名和本次退货数量始终优先保留。


## 12. 第四阶段重构范围

### 报表与导出

- 顶部必须是完整的“报表查询与导出”工作区：报表类型、日期范围、查询、导出属于同一层级。
- “指定日期库存快照”只使用快照日期；其他报表使用开始 / 结束日期，并在 UI 层先验证日期顺序。
- 查询后至少显示明细行数；按报表类型补充册数 / 库存数量 / 净库存变动和金额摘要。
- 报表表格必须重新应用统一列宽、数字右对齐和书名 / 备注 Fill 规则，不能直接使用 DataGridView 默认自动宽度。
- 小窗口优先隐藏 ISBN、供应商、原单号、出版社、分类等次要列，核心日期、单号、书名、数量和金额优先保留。
- 空结果必须显示明确 Empty State；空结果不允许导出一个看似成功但没有业务数据的 Excel。
- 导出仍使用本地 NPOI .xlsx，不依赖 Microsoft Excel，不增加联网能力。

### 供应商管理

- 增加综合搜索，覆盖名称、联系人、电话和备注；“包含停用”是明确过滤条件。
- 顶部显示结果数量、启用数量和停用数量，避免用户只从表格中猜测状态。
- 宽屏使用“供应商列表 + 右侧供应商详情”；非 Wide 宽度自动折叠详情区。
- 窄窗口依次隐藏备注、电话、联系人、启用状态等次要列，供应商名称始终保留。
- 新增 / 编辑 Dialog 使用统一表单结构，名称为必填，备注使用多行输入，Footer 固定保存 / 取消。
- 不提供物理删除供应商；停用只影响新的采购选择，历史采购单的供应商快照必须保持不变。


## 13. 第五阶段：DPI 基础修复与主框架

这一阶段不是继续“给页面加卡片”，而是先修复会让整个软件显得廉价的基础问题。

### DPI / 字体安全

- 所有主 Form 和 Dialog 统一使用 AutoScaleMode.Dpi，96 DPI 作为设计基线。
- UiTheme 会根据实际 Font.Height / TextRenderer 测量结果，为 Label、Button、TextBox、ComboBox、NumericUpDown、DateTimePicker 和 DataGridView 设置安全最小尺寸。
- TableLayoutPanel 中过小的绝对文本行会自动转换为 AutoSize；其他固定行如果小于其子控件的实际需要会自动增高。
- 禁止通过强制放大单行 TextBox 本体来模拟现代输入框高度；使用布局留白保持原生文字基线正常。
- 详情字段与表格标题统一垂直居中，不再依赖 top padding 把文字“推到看起来差不多的位置”。

### 主框架 / Dashboard

- 主导航改为暖色浅底、分组导航、左侧连续选中指示条，不再使用整块深色侧栏作为视觉主体。
- 导航、页头、副标题、状态栏全部使用内容驱动高度，避免雅黑字体在高 DPI 下被截断。
- Dashboard 指标卡在较窄窗口自动从 4 列变为 2×2；最近销售和低库存保持主次比例。
- 首页标题、说明、刷新、销售入口、新手引导和数据卡全部统一到同一 spacing / typography 系统。
- 新手引导 overlay 改为 DPI-aware、内容驱动卡片高度，并在 Form 自动缩放后重新绑定主窗口 Bounds。

### 本阶段硬验收

- 96 / 120 / 144 / 192 DPI 下，不允许出现单行文字只显示上半截或下半截。
- 1024×768 下，主导航、页面主操作和 Dialog 保存 / 取消必须可达。
- 4K 150% / 200% 下，字号、输入控件、表头和详情字段必须保持同一垂直节奏。
- 发现裁字时优先修复字体度量 / RowStyle / Padding 根因，不允许通过单页面“再加 3px”长期堆补丁。


## 14. 第六阶段：布局一致性与自动回归检查

在 DPI 基础修复之后，继续清除页面自身残留的固定布局假设。

### 页面级规则

- 业务页面中不允许再出现 10–79 logical px 的固定文本容器高度；按钮高度除外，按钮由全局最小高度规则保护。
- TableLayoutPanel 的搜索行、输入行、详情行、Footer 优先使用 AutoSize；需要视觉节奏时使用 MinimumSize，而不是把 RowStyle 锁死。
- 列表区标题、详情区标题使用内容驱动高度，并统一 10px 上下内边距。
- 详情字段使用 AutoSize 行 + 字段 MinimumSize，文字垂直居中；禁止使用大额 top padding 模拟居中。
- 单行 TextBox 保留原生文本基线；外层布局决定空间，不直接拉伸文本框本体。

### 自动回归检查

Release 自检除数据库 / 进销存事务外，还必须实例化主要 WinForms 页面并检查：

- 非 AutoSize Label 的实际高度不得小于当前字体的安全测量高度；
- 单行 TextBox 不得设置 AutoSize=false；
- 可见按钮不得低于当前字体所需高度；
- TableLayoutPanel 不得重新引入小于 80px 的 Absolute 行；
- 基准检查窗口为 1024×768，真实 125% / 150% / 200% DPI 仍需在 Windows 上做最终 smoke test。

此检查的目的不是替代真实高 DPI 测试，而是防止最常见的“文字显示一半”“输入框被固定行挤压”“按钮高度不够”等回归再次被合并。


## 15. 第七阶段：商业软件视觉层级扫尾

在裁字和 DPI 基础问题稳定后，视觉优化必须从“去掉 WinForms 默认控件感”入手，而不是增加更多装饰。

- 页面分区依靠暖灰工作区、白色 Surface、留白和层级建立边界；普通业务卡片不再使用系统 FixedSingle 黑灰边框把每块内容框死。
- SurfaceMuted 与表头使用更明确但克制的暖灰层次，DataGridView 表头和内容区需要能一眼区分。
- 主按钮保持强调色 + Bold；普通次级按钮改用 Regular 字重，避免全页面每个按钮都同等抢眼。
- 零售开单和采购入库的明细区必须有独立标题栏，明确说明表格中哪些字段可直接编辑。
- 零售开单的扫码 / ISBN 输入使用明确字段标签，不允许出现“一个孤立输入框 + 两个按钮”而缺少字段语义。
- 空状态使用两行清晰指引，告诉用户接下来应该扫码、搜索或从资料中选择。
- 图书资料使用“查询结果 / 图书详情”等用户语言，避免“图书表格”一类开发者术语。

该阶段仍坚持原生 WinForms / GDI，不通过第三方皮肤库掩盖布局和信息架构问题。


## 16. 第八阶段后续：汇总条与操作区

在搜索 / 筛选区完成内容驱动后，底部结算与汇总区也必须遵循相同原则。

- 销售、采购和退货的 Footer 不允许使用固定 136 / 146 / 150px 一类列宽承载动态中文统计文字。
- “项目数 / 册数 / 金额”使用可换行的 FlowLayoutPanel，并以弱 Surface 与 AccentSoft 区分普通统计和主金额。
- 主确认按钮放在独立 AutoSize 列，不能因为统计文字变长而被压窄。
- 备注标签与操作按钮使用 AutoSize 列；输入框占据剩余空间。
- 可直接编辑的 DataGridView 数量 / 价格单元格使用弱 AccentSoft 背景提示编辑性，但不改变业务校验规则。
- 设置页中的短表单操作采用可换行 FlowLayout，不再为了一个输入框和按钮建立固定列宽网格。


## 17. 主数据编辑与详情面板

- 新增 / 编辑 Dialog 的默认尺寸应体现桌面商业软件的信息密度，不能把 10+ 个字段压缩进过窄的小弹窗。
- 单字段容器的标签行和输入行都使用 AutoSize；单行 TextBox / NumericUpDown / CheckBox 不使用 Fill 强行拉高。
- 多行备注可以 Fill，并通过 MinimumSize 保证有效编辑面积。
- 详情面板的字段名列使用 AutoSize，不再用 78 / 86px 固定列承载中文字段名；字段值占据剩余空间。
- 长路径、长说明等内容不能通过 AutoSize 把整个页面撑宽，应使用 Fill + AutoEllipsis 或可换行文本。
- Dialog 仍通过 FitDialogToWorkingArea 限制在当前工作区内，保证 1024×768 和高 DPI 下保存 / 取消按钮可达。
